# Specialist ownership

Specialists work under their owning role and within an authorized task contract. A role is an accountability, not evidence that an agent or person is available. Escalate decisions to the Founder unless delegation is recorded. "Tech side" means the Requirements role and the Implementation role together.

| Owner | Specialist | Responsibility and output |
|---|---|---|
| Requirements | Product Owner (PO) | Canonical product requirements, feature IDs, proposed scope, business rules and measurable acceptance criteria; reconcile Business inputs and seek Founder approval where required. |
| Requirements | Risk triage | Propose the risk tier (T1-T3) with reasons; the Founder approves it. |
| Requirements | End-to-end verification | Write and run the e2e scripts against the environment the Founder names; report pass or fail with evidence. |
| Implementation | Architecture | Propose solution design, libraries, internal architecture and ADRs; keep the original architecture rules in the code repository. The Founder approves. |
| Implementation | Tech Lead function | Task DAG, lane ownership, integration and PR readiness. |
| Implementation | Development and code tests | Implement authorized contracts; write and run unit and integration tests; provide test and PR evidence. |
| Implementation | Security checklist | Apply the security checklist to the change and record evidence. |
| Business | UX/UI | User flows, accessibility assumptions and design contract. |
| Business | Marketing | Audience, positioning and campaign proposals. |
| Business | Finance | Financial assumptions, forecast and budget proposals. |
| Business | Accounting & Tax | Accounting treatment and jurisdiction-specific tax questions and evidence. |
| Business | Legal & Compliance | Identify applicable obligations, evidence and qualified review needs. |
| Business | Scenarios and business-fit | Write the scenarios of user behavior and the business rules that must not break; judge whether test results match what the business needs. |

Business, Requirements and Implementation resolve cross-domain dependencies through the handoff protocol. A specialist recommendation or test result does not itself approve scope, spending, implementation or release.
