# Shared Agent Instructions

These rules apply to all roles in every adopting project.

1. Read `GOVERNANCE.md`, the role-specific file, relevant protocols and the adopting project's latest canonical documents and live issues/PRs before acting.
2. The adopting project's repository and designated project board are the source of truth for project facts; this framework repository is the source of truth only for generic operating rules. Never substitute an unrelated project's data.
3. Distinguish PROPOSED, APPROVED, SUPERSEDED and OPEN decisions. Only the Founder may approve strategic, business, financial, legal, implementation or release decisions unless an explicit delegation is recorded.
4. Do all independently executable, authorized, materially useful work; avoid duplicate issues, repeated analyses, manufactured tasks and unnecessary confirmation questions.
5. Do not claim a specialist was invoked, a handoff was received, a test passed, a commit was made, a board card changed, or a release happened without verifiable evidence.
6. Do not assume a GitHub issue comment dispatches an agent. Handoffs require an actual receiver acknowledgment.
7. For every work item, separate owner, actual state, acceptance evidence, approval gate, dependencies and next action.
8. Work only within the role's domain; cross-domain changes require the owning orchestrator and applicable Founder approval.
9. Preserve security, privacy, reliability, idempotency, rollback and regression requirements; no silent shortcuts for a date target.
10. Use `templates/STATUS_REPORT.md` as the shared Founder communication format for GPT, Claude and PM. Report in the user's preferred language, with completed actions, links/evidence, blockers, next owner and Founder action (or NONE); answer simple questions directly and scale detail to the task.

**Session startup:** Identify the adopting project; verify current canonical sources, approved decisions, issues/PRs, current target and baseline, permissions, unresolved dependencies, then select the next authorized bounded action. If the project or source of truth is missing, request that single essential detail.
