# Bootstrap design and risk triage

Status: implementation authorized by Founder handoff 2026-11-07; publication/release approval is separate. Risk T3: project instructions govern agent behavior and can affect security. The operator must independently authenticate both the full commit and the SHA-256 of the exact archive; a digest downloaded from the same untrusted source is not an independent trust anchor. The CLI checks archive bytes against that digest but does not cryptographically establish that an arbitrary local ZIP came from the named commit. GitHub download uses the commit-specific endpoint and HTTPS. Private repositories need a read token.

The shell CLI installs a small, fixed selection of central documentation plus project entry points, a pin, schema 2 YAML configuration and a managed file hash manifest. It requires Bash and standard Unix tools, not Python. The earlier Python CLI uses a separate schema 1 and cannot update a shell-created project or vice versa; manual migration requires backup and review. Project decisions stay outside managed paths. Updates require compatible schema, unchanged managed files, diff preview and an explicit typed confirmation. Initial collisions fail closed. Prior pins can be restored with the same update command and confirmation. Normal write failures trigger restoration of earlier bytes; abrupt process or machine failure, concurrent writers and restoration failures require manual recovery from a separate project backup or version control. The operation is not an atomic multi-file transaction. No project or framework approval is implied by a version update.

Dependency graph: verified archive -> render -> conflict and compatibility check -> preview / confirmation -> guarded writes -> verification. Work is performed in one lane; no independent specialist review or QA sign-off is claimed. Automated tests cover safety paths; security and release review remain outstanding.
